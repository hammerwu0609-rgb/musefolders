## 一键启动（Windows）

双击 [启动曲境.cmd](./启动曲境.cmd)。启动窗口会显示 `http://127.0.0.1:8501`，服务就绪后尝试自动打开浏览器。保持启动窗口开启；关闭窗口即停止本地服务。如果浏览器没有自动打开，手动访问该地址即可。首次使用若没有 Python 环境，启动器会调用 `setup.ps1` 安装依赖，需要已安装 [uv](https://docs.astral.sh/uv/) 和网络连接。默认启动会安装声音地图所需依赖；首次建立模型地图时仍需等待本机完成分析。

命令行启动：先运行 `./setup.ps1`，再运行 `./run_demo.ps1`。服务只监听本机 `127.0.0.1`；不要用 `0.0.0.0` 对公网暴露原型。端口 8501 被占用时，先关闭旧服务。歌曲主题地图与语言识别需要额外依赖；要安装它们，请在执行这两个脚本前设置 `$env:MUSEFOLDERS_ENABLE_LYRICS="1"`。安装依赖不等于下载主题模型，首次下载仍需在界面里明确勾选同意。

语言地图还需把 [fastText 官方 `lid.176.ftz` 模型](https://fasttext.cc/docs/en/language-identification)放到 `models/lid.176.ftz`，或在歌词区指定本机模型路径。当前本机验证下载文件为 938,013 字节，SHA-256 为 `8F3472CFE8738A7B6099E8E999C3CBFAE0DCD15696AAC7D7738A8039DB603E83`；模型不会随项目提交，也不会自动下载。官方将其标为 CC BY-SA 3.0，未来分发时要另行履行许可义务。没有模型时语言显示“未知”，但不影响本地听感地图。DeepSeek 主题解释完全可选；如启用，先轮换曾在聊天中公开的旧密钥，再在启动曲境的本机进程设置 `DEEPSEEK_API_KEY`，切勿写入代码或提交到仓库。

## 音乐地图：当前主流程

1. 选择本地音乐来源文件夹，点击“分析此文件夹”。程序读取元数据、封面和基础声学特征；普通可读音频进入地图，受保护格式会跳过。原始音频只读。默认进入“① 找歌”。
2. 地图先显示明确标注的“基础声学地图”。点击“建立模型听感地图”，才使用随项目提供的 MusiCNN 模型生成每首歌约 200 个数的声音画像。程序优先听取歌曲前、中、后三段；结果按音频内容和模型版本缓存。听感图横向以 BPM、纵向以 BRI 为定位基准，仅在不明显破坏轴趋势且改善声音画像近邻时，才加入少量模型位置微调。横纵代表趋势而非精确刻度；找相似曲和渐变路径仍用原始声音画像计算。模型不可用时显示基础声学地图并说明原因。
3. 听感图的冷蓝→暖橙固定表示 ACT（声音活跃度），不能切换成流派等其他色义；准确 BPM、BRI、ACT 在悬停和曲目详情里展示。“地图操作”提供点选、框选和圈选：点选只查看，框选或圈选形成一批待加入的歌曲。四张地图有放大、缩小、复位；`1×/2×/4×/8×`只是查看倍率，不是歌曲之间的距离单位。歌曲点叠得太密时，打开“重叠歌曲”逐首选择。至少 12 首不同歌曲时，可从整张点阵的形状选出十二种象征性星座轮廓中相对接近的一种；星座再决定火／土／风／水元素。星座线条只作背景叠加，不移动歌曲点位。这是趣味视觉解释，不是天文学观测、性格或运势判断。分享卡在本机生成，歌曲名默认不加入，歌词和本地路径绝不加入。
4. 以当前歌曲找相似曲，或选起点、终点生成“渐变路径”；“混合歌单”可以选多首喜欢与希望避开的歌。这些操作与主题区块、地图选区、右侧单曲按钮一样，先形成“这批发现”，不会覆盖原候选。再明确选择“加入候选”“仅保留交集”或“新建候选”。候选草稿保存在本机分析档案，按音频内容去重；重扫后找不到的原曲会提示，不会替换成另一录音。严格“无人声”条件只接受试听后人工确认的曲目；条件过严时显示真实的空结果或缩短路径。可在严格条件内撤销最近一次修改。
5. 进入“② 审查”试听、勾选排除、调整顺序，再进入“③ 保存”命名。可以下载引用本地音频的 M3U8 播放清单；也可以预览并确认复制到一个文件夹，或勾选 1—3 个标签把**当前候选**分成多个文件夹。输出副本可撤销，源音乐不动。若想一次整理全库，打开“高级工具：档案与全库整理”。
6. “可选：用一句话提出筛选条件”只发送你输入的描述文字到已配置的大模型，不发送音频、歌词、曲名或路径。模型给出可编辑的条件草案和预计首数；用户确认后仍须选择如何并入候选。没有新密钥时，此项关闭，其余功能不受影响。旧聊天中公开的密钥必须先轮换，不能放进代码。
7. 四张地图共用曲目详情和候选歌单：歌曲主题地图以紧凑、不规则的可点击区块显示爱情、亲情等主题，区块面积缓慢随歌曲数变化，确切首数看数字；“待确认”在侧边，不代表某种主题。点击区块可以看歌曲与证据来源，修正主题或把歌曲列为待加入。主题相似使用文字画像，听感相似使用声音画像，两者不能混称。流派地图与演唱语言地图采用分类群岛，群岛间距离没有“类别更相近”的含义。流派地图只接纳用户逐曲试听并核对后手动保存的专业流派；原始文件流派仍展示，但不会自动成为“已核实”。歌词可来自音频内嵌标签、旁边的同名 `.lrc` / `.txt` 或指定文件夹；重复匹配需人工确认。主题模型与语言模型分别可选：前者未就绪时仍可运行本地歌词语言识别，不会把未知语言猜成某国歌曲。地图默认不上传歌词；DeepSeek 逐曲主题解释仍须单独预览与同意。

当前样本有 95 首 MP3，原有 37 首可用歌词、50 首确认纯音乐，另有 8 首有人声但缺歌词。简洁版可从 QQ 音乐补充匹配曲目的元数据和缺失歌词，再运行外部模型批量标签分析；未运行时仍使用关键词线索。原始文件流派全部写作 `Blues`，不能用作已核实的流派。已借鉴 [qqmusic-mcp](https://github.com/baoozak/qqmusic-mcp) 的只读歌曲接口；私人歌单导入及写回尚未接入产品。

## 旧版档案与文件夹整理

打开“高级工具：档案与全库整理”即可继续使用以下流程。地图与整理共用一次本地曲库分析；高级条件筛出的曲目也可用三个明确按钮送入同一候选草稿。

1. 输入本地音乐目录，或点击“浏览文件夹”更换来源，再分析。音频原件只读；`.mgg` 等受保护格式会跳过，不尝试解密。
2. 在逐曲档案里查看曲名、歌手、专辑及内嵌封面、发行时间、原始流派、本地文件创建时间，以及主要声源、调性、调式、响度、节奏、声音活跃度、声音明亮度。可选一首查看大图、试听，并人工修正主要声源；修正保存在分析档案中，重新扫描仍会保留。
3. 在“按需定制歌单”中，按曲名、歌手、专辑、原始流派、发行时间筛选，再勾选主要声源、调性、响度等级、节奏等级；活跃度和明亮度可用零到十分的双端滑块设置区间。同一栏目多选取并集，不同栏目取交集。选项数字表示满足其他条件时的曲目数；没有结果时会提示放宽哪个条件能找回曲目。一级与二级编码可以同时使用。
4. 查看筛选出的曲目，填写歌单名称。可以立即下载引用原音乐路径的播放清单；也可以预览后确认把选中曲目复制进一个文件夹，原件不动。复制操作有清单，可撤销尚未被修改的副本。播放清单引用的原文件若被移动，需要重新生成。
5. 在“整理全部音乐”中勾选 1–3 个编码标签。可分别选择“调式”（只区分大调/小调）或“调性”（区分如 C 大调与 G 大调）；系统按所选标签取值分组，文件夹名直接使用这些标签。先预览文件夹数和曲目数，再确认标签组合；可改文件夹名或纠正单曲归类。
6. 检查全部曲目的复制预览并再次勾选确认，才会向新目录复制音频与播放清单。整理清单记录本次副本，可撤销未被修改的副本。

中文/英文界面共用相同的语言无关标签值，切换语言或标签不需要重新解码音频。界面文案会随语言切换；歌名、歌手、专辑、文件路径和原始流派是用户文件内容，始终保留原文。
本地演示使用简洁工具栏模式，隐藏 Streamlit 自带的英文部署入口与设置菜单；这些并非曲境的功能，也无法通过产品内的语言开关翻译。

## 测量与边界

- **BPM**：每分钟节拍数。自动节拍检测可能发生半拍/倍拍误差；节拍证据弱时会归到“节拍待定”，不硬分慢/中/快。
- **RMS dBFS**：采样片段的平均数字电平，是响度代理，不是整首歌按广播标准测得的 LUFS。
- **调性与调式估计**：根据音高类别分布估算主音和大/小调。调式标签只保留大/小调；调性标签把主音和调式合在一起，如“C 大调”。“区分度”只表示算法内部两个候选的分离程度，不等于正确率；证据不足时两个标签均归到“待确定”。它不是逐音符旋律转写，也不能保证歌曲全程不转调。
- **声音活跃度（ACT v2）**：把 BPM 30%、RMS 数字电平 25%、打击乐比例 25% 和起音密度 20% 的固定刻度分数合成 0–100 分；不再直接引用 BRI。它表示声音的运动与力度倾向，不是情绪诊断。**声音明亮度（BRI v2）**：以频谱重心 50%、85% 频谱滚降频率 25%、3 kHz 以上能量比例 25% 合成 0–100 分；不是音色的全部属性。这些权重是可审查的工程起点，尚未经听众标注证实为心理声学最优值；移除直接引用也不等于 ACT 和 BRI 在真实曲库中统计独立。
- **主要声源**：本机运行 [Google YAMNet 音频分类模型](https://github.com/tensorflow/models/tree/master/research/audioset/yamnet)，汇总两段音频中的相关类别。只在证据明显时标注人声、钢琴、吉他、弦乐、管乐、打击乐或合成器；否则标为“待确定”。这是模型估计，不是分轨或正式演奏名单。模型文件来自 [Google MediaPipe 的公开模型资源](https://storage.googleapis.com/mediapipe-models/audio_classifier/yamnet/float32/1/yamnet.tflite)，校验值为 SHA-256 `4D8B4A53282DC83EF04E3E7DBC4FBC98082E34E44ED798E16C3A0CDD4C584FAF`。
- **当前乐器覆盖率限制**：在 95 首真实样本上，只有 7 首达到保守的自动判定门槛（钢琴 4、弦乐 2、吉他 1）；88 首为“待确定”。因此该能力只能作为辅助提示，尚不能宣称自动识别大多数曲目的主乐器。用户可以试听后人工修正，修正会持久保存；后续可替换专门面向混音音乐训练的模型。
- **原始流派**：逐曲档案忠实显示内嵌标签；95 首样本 MP3 的标签全为 `Blues`，疑似批量错误，因此不作为已核实流派参与文件夹命名。声学规则不能单独确证 J-pop、Electronic 等流派。
- **本地文件创建时间**：只能作为下载时间的参考；如果文件被复制、重建或迁移，它可能不是原始下载日期。

本轮样本技术验证：95 首可读 MP3 建成 95 个 MusiCNN 地图点，未有画像失败；4 个受保护文件仍按规则跳过。在当前 Windows 机器上，仅声音地图的 95 首隔离缓存首次索引用时 47.246 秒，重复索引用时 3.263 秒、95 首全命中缓存；这不包含逐曲基础编码和下载依赖的时间，不能推广成所有设备的速度，见[整库索引记录](./docs/evidence/sonic_full_index_benchmark.json)。10 首样本的三段分析耗时 6.235 秒，整曲分析耗时 16.443 秒；在**仅有这 10 首候选**的对比里，各首前五名邻居的平均重合率为 0.8。这只说明两种计算结果相近，不能证明推荐“合乎心意”，见[片段对比记录](./docs/evidence/sonic_benchmark.json)。此前旧版曾记录源文件哈希 0 变化；新版的人为可用性测试尚未开展，不能把程序测试等同于用户体验验收。[五人体验测试流程](./UX_TEST_PROTOCOL.md)给出可复现的完成标准。

2026-09-27 对新版 ACT/BRI 与混合布局再次做了整库实测：95 首重新提取基础声学特征，0 首失败、4 个受保护文件跳过、源文件改动数为 0；首次重算用时 611.335 秒，立即重复扫描用时 3.622 秒且 95/95 命中基础特征缓存。模型听感地图 95/95 点与向量缓存命中，BPM 横轴和 BRI 纵轴的排序一致度分别为 0.9953、0.9695。二维图前十邻曲与原始 MusiCNN 画像前十邻曲的平均重合比例为 19.16%，比仅按 BPM/BRI 定位的 17.37% 略高，但仍远不能将二维近邻当作精确听感相似度；推荐功能始终使用原始画像。在这 95 首上，BPM–BRI、BPM–ACT、ACT–BRI 的样本相关系数分别约为 −0.143、+0.353、+0.608。前两者符合“较低重合、节奏与活跃度同向”的方向性预期；ACT 与 BRI 仍明显相关，表示这批歌中活跃声音通常也偏亮，不能宣称三项统计独立。7 首 BPM 估计的可信度偏低，位置需结合试听核对。上述是这一批样本的描述统计，不是算法准确率或用户体验结论。

## 迭代接口

`TrackEncoding` 是逐曲编码档案；`CollectionPlan` 是平台无关的分类蓝图。声音画像、歌词画像分别缓存，歌词变化不要求重算音频。`CatalogReader`（列出曲目）、`AnalyzableAudioProvider`（提供可分析音频）与 `PlaylistWriter`（写入歌单）把三种权限分开；本地文件提供完整路径，QQ 音乐接口目前仍只是待验证的接入位置。仅有查询 Key 或元数据时不能假装已有可分析音频，也不能画虚构的听感地图；写入歌单还需要单独授权与映射。专业流派仍须单独建立可靠来源。

随项目提供的 MusiCNN ONNX 模型来源、校验值和许可见[模型来源说明](./models/MODEL_ATTRIBUTION.md)。曲境独立实现了地图和推荐逻辑，没有直接复制 AudioMuse 程序源代码。
