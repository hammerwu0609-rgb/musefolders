# 逐曲标签与自然语言契约

当前统一词表版本为 `local-evidence-v1`。应用分析或检索时，在 `artifacts/tag_catalog.json` 保存可检查的逐曲档案。它包含歌曲 ID、曲名、歌手、专辑、年份、音频数值、歌词状态，以及标签的维度、来源和状态；不包含歌词全文、歌词路径或音频路径。`artifacts/` 已被 Git 忽略。

每种信息按证据强度使用：

| 来源 | 档案中的表示 | 可用于检索的边界 |
| --- | --- | --- |
| 音频分析 | 速度、活跃度、明亮度；听感标签为 `estimated` | 估计数值，不是情绪或流派真值 |
| 有效歌词 | 主题标签为 `keyword_clue`，记录命中词 | 只表明关键词线索，不等于完整语义理解 |
| 用户人工确认 | 标签为 `verified` | 覆盖自动主题线索；确认的流派与纯音乐单独留证 |
| 文件元数据 | 年份及 `raw_unverified` 流派 | 缺失年份不匹配年份条件；原始流派不作为已确认流派 |

应用本地解析常用表达，比如“爱情、慢一点、安静”或“Taylor Swift 的爱情歌”，然后只检索本地档案。部分概念及否定／或条件会明确提示不支持，避免静默丢条件。主题中的“爱情”可以接纳已有“暗恋”“失恋”的标签线索；每条结果说明实际命中的子标签。

可选 AI 翻译器只接受用户主动开启后输入的那一句话，调用前要求 `DEEPSEEK_API_KEY` 环境变量。AI 只返回以下固定字段，所有字段和值都经过本地校验：

```json
{"intent":{"themes":["暗恋"],"tempo_max":95,"artist":"歌手"},"unsupported":[]}
```

允许的主题为 `爱情、暗恋、失恋、思念、成长、友情、亲情、回忆、孤独、旅途、庆祝、自然`；数值范围、年份和文字长度均有限制。模型若返回未知字段、未知主题、冲突范围或不支持的条件，程序拒绝执行。AI 从不接收歌曲列表、歌词、音频、路径或标签档案，也不决定最终歌曲结果。

当前还没有经过标注的歌词主题准确率报告，`love` 等词可能造成误报。下一阶段优先复用现有外部大模型接口：离线批量分析有效歌词，保存结构化主题、简短语义摘要、模型与来源；查询时让模型理解用户描述，再在本地结合音频条件筛选，并对候选按摘要相关性排序。这样不需要自行训练或部署歌词向量模型。本地多语言向量是以后降低调用成本或提高隐私性的可选方案。

现有 `theme_assistant.py` 只提供旧工作台的逐首节选分析，`intent_assistant.py` 只把用户查询转换为固定检索条件；它们尚未形成简洁版的全库歌词分析、缓存、语义排序闭环。接入模型后仍需检查模型输出与歌曲版本是否对应；没有人工主题标注时，可以做功能演示，不能声称已测得准确率。

QQ 音乐接入可借鉴 [qqmusic-mcp](https://github.com/baoozak/qqmusic-mcp) 的只读能力：导出“我喜欢”与歌单、通过 MID 获取歌曲详情与歌词，再合入歌曲档案。歌单创建、同步和回滚可以在只读链路稳定后对接。该项目不提供可分析的音频文件，平台歌曲若没有匹配的本地音频，就只能使用歌词与元数据参与检索，不能生成真实的音频特征。其接口为非官方接口，需单独验证登录、稳定性和歌曲版本匹配。
