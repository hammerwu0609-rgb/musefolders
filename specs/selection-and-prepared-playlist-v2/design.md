# 实现设计

## 界面方向

目的：探索结果随点击变化，保存与整理集中在预备歌单。保留左侧音乐探索和右侧歌曲区；唱片悬浮球独立于探索内容。

沿用既有唱片收藏风格和项目设计系统：绿色 `#31c27c`、深绿 `#1d291f`、暖金 `#c9b174`、浅金 `#eedfc4`。标题沿用 `Songti SC / STSong / SimSun`，正文沿用现有字体；采用现有 SVG 图标。保留 Streamlit v2 组件、D3 和原生 CSS，以避免为此次交互改造更换框架或字体。

## 临时选择

`workspace.js` 中管理单曲、板块、全库手选三种互斥结果。全库勾选只修改浏览器中的临时集合；探索替换手选集合先经过覆盖提示。提示确认后统一清除旧集合、条件和焦点，再应用新的点击结果。

选中歌曲无复选框。全库保持完整范围，切换显示标签不改变选择。播放状态独立管理。

每次选择改变增加代次标识。请求记录提交时的代次；只有保存响应对应当前代次时，才能清空提交的选择。失败响应保留选择。请求标识与 `added` 标识共同控制成功动效。

## 保存模型与兼容

保留 `PlaylistDraft` 版本 2 的来源条目与成员快照，增加可选的 `order` 指纹列表。旧数据没有 `order` 时沿原条目展开顺序恢复；不更改归档标识或自定义名称。

`items` 仍是来源汇总后的去重兼容视图，`excluded` 表示当前预备歌单中被删除的录音；来源快照保留以支持撤销、解释和重新加入。有效歌曲列表、数量及导出始终过滤 `excluded`。

后端增加 `delete_song`、`move_song` 和 `undo_delete` 操作。删除对当前歌单的录音全局生效；逐曲排序不改写板块成员快照。重新加入相同板块可重新启用被删除的成员，普通重复加入只补充来源，不虚增计数或播放新增动效。

撤销在 20 秒内有效，保存删除前的草稿及删除后的版本；若歌单发生其他变更则拒绝使用旧撤销，避免覆盖新编辑。

前端通过 `playlist.songs` 读取有效的逐曲视图，包含内容指纹、可重新定位的曲目 ID、缺失提示和所有来源。管理、改名、切换、导出继续复用现有服务。

## 悬浮球

Pointer Events 区分点击和拖动，键盘方向键可移动、Home 可重置。位置作为本机界面偏好保存在 localStorage；失败时反馈仅本次保留。按视口和播放器实际顶部约束位置，缩放时重新计算。

抽屉保留焦点约束和 Escape 关闭。覆盖提示使用独立可访问弹窗。加入动画每次读取球体实际位置，减少动态效果时静态反馈。

## 验证

使用 Python 测试验证来源重叠、全局删除、重新加入、撤销、逐曲排序、保存失败和旧格式恢复；使用实际浏览器验证临时勾选、覆盖确认、保存后清空、完整板块、逐曲标注、拖动、布局及键盘。

本轮只更新本地代码与预览，云端发布另行处理。
