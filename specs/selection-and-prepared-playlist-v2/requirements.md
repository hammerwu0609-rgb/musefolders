# 选择跟随点击，整理集中在我的预备歌单

日期：2026-10-08。阶段：新版需求与验收规则整理。

## 用户确认与范围

本稿替代上一轮中“复选框立即保存”“板块卡片展开快照”“单曲与板块分别移除”的交互要求。

用户已补充确认：**板块结果也取消复选框，整板块加入；板块来源在预备歌单中的歌曲旁标注；所有整理发生在预备歌单内。**

界面统一使用“选中歌曲”作为临时结果区域名称。全库歌单保持已导入、成功声学分析的歌曲范围。我的预备歌单负责歌曲集合的持久保存。音频、歌词、地区资料及云端现有音乐保留；本轮规划不包含云端发布。

## 用户目标

- 探索时点击单曲或板块，即可看到唯一的当前选择，不受上一次选择干扰。
- 从全库连续勾选待加入歌曲，并在跳去探索前获知未加入结果可能被覆盖。
- 将当前单曲或完整合集明确加入预备歌单，然后在预备歌单内逐曲删除和排序。
- 看清每首歌是通过什么地区、氛围、主题、框选或检索条件加入的。
- 随手移动预备歌单悬浮入口，减少遮挡。

## 1. 当前选择只有一种类型

| 当前选择 | 触发方式 | 选中歌曲中的复选框 | 加入行为 |
| --- | --- | --- | --- |
| 单曲 | 点击歌曲行、歌名或探索光点 | 无 | 点击“加入我的预备歌单”，保存该曲 |
| 板块／合集 | 点击地区、氛围、歌词主题、星图框选或提交搜索 | 无 | 点击“整板块加入预备歌单”，保存完整结果 |
| 全库手动挑选 | 在全库歌单勾选一首或多首 | 无；勾选操作保留在全库 | 点击“加入所选歌曲”，保存全部勾选结果 |
| 空选择 | 清除选择，或当前结果全部加入成功 | 无 | 显示探索引导 |

选择类型由操作来源决定。一首歌曲的板块结果仍保留板块来源；只有直接点击单曲才进入单曲选择类型。

当新点击产生选择时，系统应替换旧选择，不能将单曲叠加到旧板块，或把旧勾选合集隐式混入新选择。播放状态独立，选中操作不自动播放或加入。

若保留“返回该板块”，它应作为重新选择该板块的显式操作，而不是维持单曲和板块同时选中。

## 2. 全库勾选形成临时待加入集合

- 勾选歌曲时，选中歌曲同步包含该曲；取消勾选时，同步移除该曲。
- 勾选不写入预备歌单，也不触发保存成功反馈。
- 全库连续勾选时保持全库视图，实时更新“选中歌曲（N）”；用户可切换查看临时结果。探索点击产生新选择时打开选中歌曲。
- 当全库勾选集合非空、尚未加入预备歌单且新操作会替换它时，先提示：“当前有 N 首待加入歌曲，继续探索可能覆盖这些选择。”
- 提示提供“继续探索”和“返回继续选择”；取消替换时保留原选择、复选框和当前结果。提示不得自动替用户保存。
- 用户确认继续后，应同时清除旧全库勾选状态与旧待加入集合，再显示新结果。
- 切换全库／选中歌曲两个显示标签、试听歌曲、打开抽屉或移动悬浮球不属于覆盖操作。

## 3. 板块整批加入，预备歌单逐曲显示

- 选中板块无复选框，也无逐行加入按钮；保留独立试听按钮。
- 整板块加入必须使用完整匹配结果，不能只保存滚动列表中已显示的歌曲。
- 预备歌单始终按歌曲行展示，不再显示板块卡片或点击板块展开预览。
- 通过板块加入的每首歌曲显示来源标注，例如“地区：日本”“主题：爱情”“星图框选：节奏指数…／明亮度…”“搜索：睡前听的歌”。
- 全库手动挑选及直接点击单曲的来源分别标为“全库手选”和“单曲加入”。
- 同一录音由多个条件加入时，只显示一首歌，合并来源标注；来源文字只解释加入原因，不触发整板块选中。
- 来源条件及加入时成员应保留为记录，后续探索或资料更新不能悄悄修改已保存歌曲及其加入原因。

## 4. 预备歌单中的删除与整理

- 每首歌提供明确的“删除”按钮，并保留播放、向前／向后移动。
- 删除一首歌时，应将它从当前预备歌单的有效歌曲集合移除，即使它来自多个板块或同时由手动加入。来源重叠不能让歌曲立即重新出现。
- 删除仅影响当前预备歌单；全库歌曲、音频文件、云端音乐和其他已保存歌单不受影响。
- 删除后计数、排序及 M3U8 导出同步更新；保留短时“撤销删除”操作，恢复原顺序与来源标注。
- 用户日后明确重新加入相同单曲或板块时，允许重新加入此前删除的歌曲；历史上加入过该板块不能导致本次请求整体被当作无效重复。
- 删除正在播放的歌曲不应打断已开始的音频播放；后续播放队列依据新的预备歌单成员更新。
- 新建、改名、切换已保存歌单、导出继续可用。

## 5. 保存成功后，当前待加入歌曲消失

- 我的预备歌单持久保存曲目；选中歌曲及全库勾选仅保留本次临时操作状态。
- 只有服务端确认保存成功后，才更新预备歌单成员、数量及成功动效，并从提交时的当前选择中移除已保存曲目。
- 单曲或整板块全部加入成功后，选中歌曲显示空选择引导；手动勾选加入成功后，全库对应复选框同步取消。
- 保存失败时，保留当前选择和勾选状态，提示失败原因，不触发成功动效。
- 若请求处理期间用户已经切换到新的探索选择，旧请求的成功响应不得清空新的选择。
- 全库中已保存的歌曲继续存在，显示“已加入预备歌单”。对没有新增有效歌曲的重复加入，不增加计数或播放新增歌曲动效。

## 6. 可拖动的预备歌单悬浮入口

- 将左下固定入口改为可拖动的唱片悬浮球，显示去重后的保存歌曲数量；单击打开或收起预备歌单抽屉。
- 延续现有黑绿界面和暖金唱片标识，抽屉使用逐曲列表。
- 桌面支持鼠标拖动，移动端支持触摸拖动；拖动结束不能误触抽屉开关。
- 球体不能移出可用视口、压住底部播放器或进入设备安全区域；窗口缩放后重新约束位置。
- 位置作为界面偏好在本机保留，并提供“重置位置”。这不等于保存临时歌曲选择。
- 键盘用户能够打开、关闭和重置入口，抽屉保持焦点管理及 Escape 关闭。
- 加入动效飞向球体当前所在位置；减少动态效果时使用静态反馈。

## 7. 管理入口命名

主界面“管理曲库”更名为“管理曲境”，同步修改可访问名称和相关入口提示。管理流程内的导入、资料、账号连接、分析等功能继续可用。

## 已报告的交互冲突

| 场景 | 处理规则 |
| --- | --- |
| 全库勾选多首后点击探索单曲或板块 | 先给覆盖提示；确认后完整替换，取消则保留旧集合。 |
| 已选择板块后点击其中一首歌曲 | 直接变为单曲选择；旧板块不再作为当前选择。 |
| 一个板块仅匹配一首歌 | 仍保留板块来源，整批加入按钮可保存这一首；不形成双重选择。 |
| 播放 A 时选中 B 或新板块 | 播放继续，选择切换；播放不是选中状态。 |
| 旧加入请求等待保存时产生新选择 | 保存结果只处理提交时选择，不能误清空新选择。 |

当前没有必须同时维持“单曲焦点”和“板块选择”的业务需求。如后续引入多条件叠加或跨板块累积挑选，需另行报告并确认交互。

## 旧数据兼容要求

当加载上一轮的单曲／板块条目时，系统应展开完整成员、按音频指纹去重，并将原板块条件附着到歌曲来源标注。已有名称、有效歌曲、歌曲展开后的顺序、已排除状态及归档标识应保留。

当音频缺失时，系统应显示逐曲“待找回”；不得使用另一录音替代。M3U8 应仅输出有效歌曲的去重播放顺序，不包含来源标注。

## 重点验收条件

1. 当用户连续点击两个单曲或两个板块时，选中歌曲只显示最后一次结果。
2. 当用户选择单曲或板块时，选中歌曲中均没有复选框；播放按钮不触发选择替换、加入或删除。
3. 当用户在全库勾选三首后取消一首时，选中歌曲数量由三变二，预备歌单数量不变。
4. 当未保存的全库挑选即将被覆盖时，取消提示可完整保留两首及其勾选状态；确认后只显示新选择。
5. 当含 23 首的板块仅显示前 12 首时，整批加入应保存全部 23 首，预备歌单显示 23 个带来源的歌曲行。
6. 当两个重叠板块及手选含有同一录音时，预备歌单只有一行，来源完整；删除它后计数与导出均不再包含它，其他歌曲保留。
7. 当用户重新加入包含此前删除歌曲的板块时，该歌曲应重新出现，且无重复行。
8. 当保存成功或失败时，当前选择分别清空或保留；成功响应不得清空请求期间产生的新选择。
9. 当拖动球体、缩放视口或使用手机时，入口不误开抽屉、不超出边界、不遮挡播放器；加入动效使用球体的新位置。
10. 当恢复旧草稿或已保存歌单时，逐曲列表的名称、顺序、来源、缺失提示与 M3U8 去重导出正确。

验收还应覆盖桌面、1280×720、约 390px 手机宽度、键盘操作、减少动态效果、保存失败、播放连续性及旧数据迁移。
